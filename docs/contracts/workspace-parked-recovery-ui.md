# VM reconstruction: parked recovery and exact saved-source labels

This new candidate is based on public1275662, not a byte restoration of lost private982047/0b24 source. It changes frontend only; recovered private backend and public storage defaults remain untouched.

## Researcher task and cost

A returning researcher can have an unresolved exact intake/Prepare identity after a lost response and reload. Current anti-replay safety deliberately blocks another same-feature request; no payload can be reconstructed from its key. The baseline source and tests confirm that unknown state can indefinitely block unrelated work. Generated file paths also make saved evidence choices harder to recognize, although exact source preselection already works.

An explicit Park warning/confirmation retains that identity; a separate Start a separate intent action permits independent work without localStorage deletion, CLI use, or replay. These necessary confirmations are added costs, not a measured click/latency improvement. Users without unresolved requests keep the existing path. Source cards still show title and declared coverage; labels reuse the exact existing source/artifact binding.

## Invariants

- Original v1 pending identities are unchanged. Opaque disposition markers live in a separate versioned origin/workspace/project/type/key namespace. No title, text, locator, path, purpose or credential is stored in a marker. Invalid/orphan markers grant no authority; old clients still conservatively block original pending identities.
- Parking is not backend cancellation, failure proof or completion. It sends no request and creates no new key. Sending/checking, known-unsent and found entries cannot be parked. Same-key replay of a parked entry is refused even if a live payload remains. Exact read-only checks, including parked conflicts, remain available with the existing bounded startup limit.
- Both hook submission guards and visible blocked state exclude explicitly parked entries. Existing payload-bearing forms remain locked until the separate-intent action. That explicit action clears intake fields, or abstract range/purpose/request association. It does not submit, select text, Run, or silently retry old input with a new key. New IDs are created only on a later explicit save/Prepare; known-key collisions fail closed.
- Durable parking requires the original pending identity still be durable. Storage failure does not unlock until an explicit session-only choice; reload may conservatively block again. No cross-tab synchronization or server cancellation contract is claimed.
- Legacy keyless Prepare uncertainty cannot be reset by an unrelated parked entry or ordinary rerender. Scope/newer-navigation/failed-refresh/cache guards remain in force. Late found results remain retrievable separately rather than taking over a new form or navigation.
- Labels join intake version/artifact ID/hash with source_record_id/project/origin. Similar titles are never identity evidence. Title, declared coverage and valid local recorded/registered date are descriptive, not publication/reading/human-verification claims. Path remains secondary; missing linkage is visibly unverified, stale file options remain disabled, and IDs remain option values. Rendering labels does not read source text or invoke a model.

## Verification and limits

Red baseline and new focused/full-App regressions cover disposition privacy/persistence, storage failure, corrupt/scope-mismatched markers, conflict checking, repeated actions, explicit separate transitions, keyless uncertainty, newer navigation and exact labels. Test logs and frozen hashes are retained separately. Mock DOM/type/build results are not browser/native zoom/keyboard, installed-runtime, semantic or researcher acceptance. No BLOB UI integration, backend change, provider, native Windows retry or public publication is included.
